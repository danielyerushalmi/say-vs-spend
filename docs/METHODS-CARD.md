# Say vs. Spend: methods card (one page, for judges)

> Commit IDs in this file are from our development repo, which is private. This public repo is a one-commit clean copy; the full commit list with times is in `docs/DEV-HISTORY.md`.

Every number comes from `frontend/runs/say_latest.json`, except red-team checks, which cite `docs/RED-TEAM.md`. Labels: **MEASURED** (real public data), **SYNTHETIC** (AI crowd), **ESTIMATE** (our rough number), **EXPLORATORY** (not part of the pre-registered test).

## Question

Did an AI crowd of shoppers understand which online brands people actually spend on, or did it just pick the famous ones?

## Data

| Source | What | Label |
|---|---|---|
| SEC data API (`data.sec.gov`) | Yearly revenue for 6 public companies that sell mainly online | MEASURED |
| Flashpoint synthetic panel, 200 AI shoppers (main run) | Heard of it (yes/no); website quality 1-10; likely to buy in 12 months 1-10; buys this kind of product (yes/no). Brand order shuffled per shopper. | SYNTHETIC |
| Flashpoint, a second panel of 200 different personas from the same persona model (gpt-5.4-mini) (repeat run) | Same first three questions | SYNTHETIC, EXPLORATORY |
| Wikimedia page-view API | English Wikipedia views over 365 days, 5 brands (no Revolve article found, three titles checked; BARK uses the BarkBox article). Added at 12:24, after the main result was seen. | MEASURED, EXPLORATORY |

Flashpoint's own metadata says the answers were generated by "gpt-5.4-mini," marked "uncalibrated."

## Pre-registered rule (exact text from the run file, `trust_card.rule`)

> Pre-registered 2026-11-14 11:47; amended 12:10 after the panel ran but BEFORE any result was computed or seen: the label comes from the LOW end of the 90% wobble range (5th percentile of a bootstrap over brands) of the Spearman rank agreement between the crowd's intent ranking and the revenue ranking. Low end 0.7 or higher = trust it; 0.4 to under 0.7 = double-check it; under 0.4 = ask real people.

Also pre-registered at 11:47: the crowd "beats fame" only if its intent score is higher than the fame ("heard of it") score. Nothing else was pre-registered. The run file holds 12 rank scores against revenue (counting the repeat panel and the 8-brand sensitivity); all but the intent score are EXPLORATORY.

With 6 brands, "Trust it" needs a near-perfect ranking. A red-team probe found that swapping just the top two brands drops the label to "double-check it" (`docs/RED-TEAM.md`). We did not change the rule after results. Separately, at 13:30 (after the results were known) we added one EXPLORATORY rule for the store-owner tool: website and fame questions get "Promising for perception, not proven" when the score vs. revenue and the agreement between two AI crowds are both at least 0.7. It never applies to buying, and the main result did not change.

## Checks performed

- Independent recount from the raw CSV by separate code: 0 mismatches, 4,800 answers (`say/audit/RECOUNT.md`). Its own bootstrap (different seed) gave intent -1.00 to 0.74; low end still far under 0.4.
- Repeat run with a second panel of 200 different personas from the same persona model (gpt-5.4-mini): same label. This shows consistency, not correctness.
- 8-brand sensitivity (run file `extras.sensitivity`, EXPLORATORY, display only): with FIGS and CarParts.com added, intent vs. revenue = -0.14 (range -0.78 to 0.54), same label. Red-team check (`docs/RED-TEAM.md`, EXPLORATORY, script outside this repo; UNVERIFIED: not reproducible from here): bootstrap over the 200 personas (brands fixed, 2,000 draws): intent median -0.14, 5th to 95th percentile -0.49 to 0.14. The verdict does not change.
- After the red-team review, exact p-values were added to the code and the "could be chance" flag now uses them. The label did not change.
- Re-ran the full pipeline from saved files with no model calls: scores, repeat block, Wikipedia block and trust card matched the saved run exactly. This check came before the 12:57 model run; that run changed only AI-generated text (draft question, reason sentence, WHY summaries) and the cost line, not any score or the label (git diff of the run file, commit `0c22195`).
- 253 automated tests for Say vs. Spend pass (`say/tests`), plus 101 for the earlier Crowd Coach prototype (`agent/tests`); committed code, Nov 14.
- Revenue from the SEC data API; online-sales evidence from each company's own investor pages or annual report (`say/brands/VERIFICATION-NOTES.md`). No anti-bot bypass was used. Hims's investor site showed a challenge and we stopped there. For Stitch Fix, curl got a challenge page and a plain Scrapling request (no bypass options) returned the page (`say/brands/stitchfix.json`).

## What would change our mind

- **A bigger brand set** (for example 20 or more, picked by a rule before any survey) where the low end of the intent range clears 0.4.
- **Real shoppers on the same questions.** If real people also miss revenue, the problem is the answer key, not the AI crowd.
- **Website-only sales data** instead of total revenue. Revenue measures business size (customers x spend per customer), not how many people buy, so a crowd could be right about who shops and still miss revenue.
- **A calibrated persona model** that ranks the same brands closer to revenue.
- **A different repeat crowd that disagrees** with the first. Today the two panels agree (0.89, SYNTHETIC vs. SYNTHETIC), so a different draw of personas from this model does not explain the miss. Both panels come from the same persona model, so a different model, or a different draw of brands, still could.
